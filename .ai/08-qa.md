## Performance/Security Notes
- Cloudflare Worker startup from latest builds: ~12-18 ms.
- Production API endpoint sweep responsive under manual curl smoke tests.
- Database access decision: production routes use Supabase REST/fetch per request to avoid Cloudflare Workers TCP socket I/O isolation. `postgres-js` singleton must not be used in Workers route handlers.
- Auth caveat: rapid repeated login stress can trigger DB-side pgsodium/argon2 RPC invalid_password/throttling; normal single login flow succeeds. Do not use rapid login loops as the pass/fail criterion.
- `hash-wasm` was tested and rejected because Cloudflare Workers disallows runtime `WebAssembly.compile()` for that package.

## Current Blockers
- Google Drive upload remains blocked by OAuth `invalid_grant` until a valid refresh token is supplied.
- Full WA connection/QR scan and actual whatsapp-web.js message sending cannot be end-to-end verified on Cloudflare Workers without an external Node runtime/session host for whatsapp-web.js.
