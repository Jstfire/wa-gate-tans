## Latest QA Status (2026-05-23)

### QR Refresh Live Browser QA — PASSED
Context: user required QR refresh to work directly from WA Gate web and to verify by live browser button click.

Steps performed:
1. Logged in to `https://wa-gate.buseldata.com/login` as authorized user.
2. Opened `https://wa-gate.buseldata.com/wa-connection`.
3. Confirmed QR images rendered for both runtimes.
4. Captured DOM image hashes before refresh:
   - Primary: `ed3198be`, image length `6322`
   - Backup: `d3ebccdf`, image length `6342`
5. Clicked `Refresh QR primary` in live browser.
6. Waited for disconnect/connect/poll cycle.
7. Captured DOM image hashes after refresh:
   - Primary: `99f869ca`, image length `6258`
   - Backup: `d3ebccdf`, image length `6342`

Result:
- Primary QR changed visibly in DOM after button click.
- Backup QR stayed unchanged.
- This proves selected-runtime QR refresh works from WA Gate web.

Root cause fixed:
- Backend already returned fresh QR.
- UI was not reactive because `qrFor(runtime.kind)` was evaluated in the parent `<For>` callback instead of inside `RuntimeCard` as an accessor.
- Fixed by passing `qrFor` function into `RuntimeCard` and calling `qrData()` inside component.
